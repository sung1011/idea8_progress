# 上班鼓励器

菜单栏里的本地工时计薪器。点一下菜单栏图标，就能看到今天赚了多少、现在的速度、今天的工时进度，以及本月累计。

数字跟着时钟和排班走，没有开始/停止计时。应用是 macOS 菜单栏代理（`LSUIElement`）：运行后没有 Dock 图标，也不会占着主窗口。月薪和排班只写在本机 `UserDefaults` 里。

- 显示名称：上班鼓励器
- Bundle ID：`com.sung1011.idea8progress`
- 系统要求：macOS 13 或更高
- 工程：`idea8Progress.xcodeproj`（SwiftUI，可在 Apple Silicon 上的 Xcode 直接打开）

## 用 Xcode 打开并运行

1. 安装 Xcode 15 或更高版本。
2. 双击仓库根目录的 `idea8Progress.xcodeproj`。
3. 顶部方案选 `idea8Progress`，运行目标选 `My Mac`。
4. 如果签名失败：选中 `idea8Progress` target → Signing & Capabilities → Team 选你的 Apple ID。只在本机调试时，用 “Sign to Run Locally” 即可。
5. 按 `⌘R` 运行。
6. 看屏幕**顶部菜单栏**（右边状态图标那一排），会出现 `¥金额` 和一个状态图标。正在入账时是播放图标，当前不计入收入时是暂停图标。这不是按钮。Dock 里不会出现图标。
7. 点这个图标打开面板。主面板只有四个指标、「设置」和「退出」。月薪和排班在「设置」里。MacBook 刘海如果挡住了图标，按住 `⌘` 再拖动菜单栏图标。
8. 要退出应用，用面板底部的「退出」。停掉 Xcode 的 Run 也会退出。

单元测试：`⌘U`。规则都在 `idea8ProgressTests/earningsChecks.swift`。

## 面板上的四个数

统计范围是**当前自然月**。设：

- 净带薪小时 =（下班 − 上班）− 与午休重叠的部分
- 折算时薪 = 月薪 ÷（本月勾选的工作日天数 × 净带薪小时）
- 今日有效秒数：今天从带薪窗口开始，到现在为止已经走过的时间。扣除午休，也不含上班前、下班后。今天不是勾选的工作日时为 0

| 指标 | 怎么算 |
| --- | --- |
| 今日已赚 | 折算时薪 × 今日有效秒数 ÷ 3600 |
| 速度 | 此刻落在带薪窗口里时等于折算时薪，否则为 0 |
| 工时进度 | 今日有效秒数 ÷ 一个满勤日的净带薪秒数 |
| 本月累计 | 本月今天之前的工作日数 × 一日满勤金额 + 今日已赚 |

一日满勤金额 = 折算时薪 × 净带薪小时。

本月工作日天数按**整月**算，包含今天和还没到的工作日，用来把月薪摊开。已经过去的工作日各按一整天满勤计入。今天不算满勤，只算到此刻已经走过的带薪时间。

举例：今天是 3 号，而且 1 号、2 号都是勾选的工作日，本月累计 = 2 个满勤日 + 今天已经走过的带薪时间。默认排班不勾选周末。2026-11-03 是周二，1 号是周日，所以只补 2 号那一个满勤日。

没有单独的时薪输入。改月薪、工作日或每日净工时，折算时薪和速度都会跟着变。

## 什么时候入账

这一秒落在带薪窗口里，就入账。带薪窗口指：今天是勾选的工作日，在上班到下班之间，并且不在午休。不需要、也没有计时开关。

所以：

- 人在工位上、时刻也在带薪窗口里，今日已赚和工时进度会自己往前走
- 午休、上班前、下班后，速度是 0。今日已赚停在已经走过的带薪时间上，不会倒退
- 没勾选的星期（默认周六、周日）同样不计
- 关掉应用再打开，不会补一段“离开期间有没有按下计时”。今天仍按排班从上班算到现在，以前的工作日仍按满勤

已过工作日和今天是两套数：昨天按一整天满勤进本月；今天只算从上班到现在、扣掉午休之后的部分。

## 设置

主面板不编辑金额和排班。点「设置」进入同一窗口里的设置页，可以改：

- 月薪（元）
- 工作日
- 上班、下班
- 午休

设置页会立刻显示按当前月薪和排班折算出的时薪。点「完成」回到四个指标。

## 默认排班

可以在设置里改，不改的话是：

- 工作日：周一到周五
- 上班 10:00，下班 20:30（本地时间）
- 午休 12:00–14:00，这段不计入带薪时间
- 净带薪工时：10.5 小时 − 2 小时 = **8.5 小时**

上下班和午休都是同一天内的时间。改完之后，今天已走过的带薪时间会按新窗口重算，已过工作日的满勤金额也会跟着新的净工时变。

默认月薪 15000 元只是占位，请在设置里改成自己的。时薪不单独填写，一律由月薪、本月工作日和每日净工时折算。以前存档里如果写过时薪、计薪方式或计时区间，读出来后会忽略；计时区间会在这次读取时从存档里删掉，只留下月薪和排班。

## 怎么验证

### 自动

在 Xcode 里按 `⌘U`。覆盖了这些行为：

- 默认净工时是 8.5 小时，午休从窗口里扣掉
- 不需要计时开关：人在带薪时段里，今日已赚和速度就按秒增加
- 刚到上班时刻速度变为折算时薪，已赚仍是 0
- 午休、班次外、非工作日不开新收入；午休前已经赚到的保留
- 跨过午休只计午休两边
- 已过工作日按满勤
- 今天不会被再加一份满勤
- 1 号和 2 号都是工作日时，3 号的本月累计是两个满勤日加上今天已过的带薪时间
- 2026 年 11 月按默认排班有 21 个工作日；月末如果今天也上满，本月累计等于月薪
- 改月薪会按同样比例改速度
- 旧存档里的计时区间和时薪读出来后不再参与计算，重新保存也不会写回去

### 手动（任意时刻都能做）

1. 打开面板。确认能看到四个指标、「设置」和「退出」，没有「开始计时 / 停止计时」，也没有月薪输入框或计薪方式切换。
2. 点「设置」。确认周一到周五是选中的，上班 10:00、下班 20:30、午休 12:00–14:00，并写着每日净带薪 8.5 小时。
3. 月薪填 `642600`。设置页应显示折算时薪。2026 年 11 月是 21 个工作日，时薪为 `¥3,600.00/小时`。点「完成」。主面板速度说明里也是这个时薪，本月累计说明里的每日金额为 `¥30,600.00`。其它月份工作日天数不同，时薪会跟着变，这是预期行为。
4. 为了不依赖现在是不是上班时间：再打开「设置」，把「上班」改到当前时间的几分钟前，「下班」改到一两小时后，午休改成 `00:00–00:30`（不要盖住现在），并确认今天的星期是勾上的。点「完成」。班次变短后净工时变少，折算时薪会高于 `¥3,600.00/小时`，这是预期行为。
5. 不用按任何开始按钮。状态应是「正在入账」，速度等于主面板上写的那条折算时薪，不是 `¥0.00/小时`。停几秒，今日已赚会增加，工时进度的时分秒在走。菜单栏图标是播放样式。折算时薪仍是 `¥3,600.00/小时` 时，大约每秒增加 1 元。
6. 打开「设置」，把午休改成盖住当前时间，但不要盖住刚才已经走过的上班时间，再点「完成」。状态变成「当前不计入收入」，速度回到 0，工时进度停住。今日已赚停在午休前已经走过的那段。
7. 把午休移开，让现在重新落进上班时间内。不用再点开始，今日已赚会继续增加。
8. 把「上班」改到当前时间之后。今日已赚回到 `¥0.00`，速度是 `¥0.00/小时`，状态是「当前不计入收入」。
9. 把排班改回默认（10:00–20:30，午休 12:00–14:00），月薪仍用第 3 步的 `642600`。日满勤应显示 `¥30,600.00`（3600 × 8.5）。本月累计 = 这个金额 × 面板上的「已过工作日」天数 + 今日已赚。今天本身不在那个天数里。

月薪 `17850`、排班保持默认时，2026 年 11 月折算时薪是 `¥100.00/小时`，日满勤 `¥850.00`。
